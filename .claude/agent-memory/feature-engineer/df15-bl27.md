## Where duplicates come from (parangonar 3.3.3; `scripts/eval_duplicate_matches_df15.py`)
- BOTH steps make them. Per-pitch DTW (`unique_alignments`): a DTW path row mapping one score
  onset to two performed onsets lets a later x claim a y already used -> one performed note
  matched to two same-pitch score notes (perf-side). Ornament step: ornamented notes re-matched to
  the earliest insertion within ±2, insertion never removed -> perf-side groups among ornamented
  notes (Debussy L.123/4, Ravel Scarbo: chords with tremolo/trill marks) and score-side groups.
- Key-sensor (100 F-08 copies), floor (150), dev (BL-18b, 598 clean): ~all perf-side pitch-step;
  ornament-step groups show up only in ornament-heavy repertoire (held-out probe: 65 of 88).
- Also: identical (s,p) pairs listed twice, and a performed note listed as both match and
  insertion (ornament step re-adds the old partner as insertion) -> harmless, but count groups
  on the SET of matches.
- Attribution trick: subclass `CleanOrnamentMatcher`, call super once with
  `process_ornaments=False` on deep copies (grace onsets are shifted IN PLACE), patch
  `pianolens.align.core.DualDTWNoteMatcher` with a factory. Final alignment unchanged (checked).
- Loading scripts by path: register the module in `sys.modules` before `exec_module`, or
  dataclasses crash (`cls.__module__` lookup).

## Fix (`align/postpass.resolve_duplicate_matches`, `correctness(resolve_duplicates=True)`)
- Greedy one-to-one: |pitch diff|, |onset - LOO expected onset| (unique matches only), score
  onset, perf onset, indices. Loser may re-match a free same-pitch note within 100 ms (BL-23
  window), else missed / extra (then normal wrong-pitch pairing). Off = byte-identical to HEAD.
- Summary keys `n_duplicate_matches_resolved`, `n_duplicate_rematched`.
- GT (nASAP, all 1,060 usable ASAP perfs, `--set asap`): 611 removed matches, 553 repairs / 58
  breaks; losers 478 truly unplayed vs 90 played elsewhere; rematches 19 right / 23 not (weak,
  n small, mostly ornament-step) -> the rematch step is the least supported part. F-08 set alone:
  33 / 3. 1 ASAP job failed on a NaN `robust_note_alignment` read in my script (fixed after).
- Regression case: ASAP Scriabin Op.8/11 Shi08M, n268 -> {n300-1, n309-1}; 2 s alignment.
